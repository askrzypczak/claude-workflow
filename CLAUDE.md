# claude-workflow

Claude Code plugin marketplace (`askrzypczak-plugins`) holding the `ticket-workflow` plugin. See README.md for contents and install.

## Conventions
- **Bump the version in every PR that changes the plugin**: `version` in `plugins/ticket-workflow/.claude-plugin/plugin.json`, in the same commit. Patch for wording or doc fixes, minor for behaviour changes. **One bump per PR, measured against `origin/main`'s version**: follow-up commits on an open PR (review fixes, feedback) keep the bump already made; only raise it further if the change grows enough to need a bigger level (patch -> minor), never step it again for the same PR. Claude Code updates installed plugins by comparing this version, so an unbumped merge may never reach agent sessions. `marketplace.json` has no version. CI enforces this on pull requests with `scripts/check-version-bump.sh` (any change under `plugins/ticket-workflow/` needs a version above the base branch's, checked on the merge ref). `main` requires that check on an up-to-date branch, and `.github/workflows/update-prs.yml` keeps open PRs current after every merge to `main`: it merges `main` in, re-raises a version another PR already took (same level, on top of `main`'s) and re-runs CI, so expect bot commits on your branch and pull before pushing. Conflicting PRs it leaves to `resolve-conflicts`.
- Keep README.md's Workflow list in step with `skills/work-ticket/SKILL.md`.
- Validate with `claude plugin validate .`; type-check TS with `npm run typecheck`; self-test the bump check with `scripts/test-check-version-bump.sh` and the PR updater with `scripts/test-update-pr-branch.sh` and `scripts/test-update-prs.sh`.
- Guardrails: the git guard and the comment guard both ship with the plugin (`plugins/ticket-workflow/hooks/guard-git.sh` and `guard-comments.sh`; tests: `test-guard-git.sh` and `test-guard-comments.sh` in the same directory, run in CI). Deny rules stay per project; this repo's own are in `.claude/settings.json`, which also wires the git guard directly for local sessions.
- Maintainer: `askrzypczak`. Branch per change, PR to `main`; humans merge.
- **Public repo**: tracked files must not contain home-directory paths, personal emails (GitHub noreply is fine), tokens, names of unpublished repos or projects, or role references to a named person (use "the human" / "the maintainer").
- `.github/workflows/ticket-labels.yml` is a reusable workflow that checks out this repo and runs `plugins/ticket-workflow/scripts/ticket-labels.ts`; callers need no secrets.
